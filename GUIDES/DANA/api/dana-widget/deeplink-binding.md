# Deeplink Binding

This Deeplink is used to redirect user's to DANA App in order to initiate account binding process, allowing them to register or login directly within the DANA App. For the easiest integration, use DANA's Libraries to implement [DANA Widget Binding](https://dashboard.dana.id/api-docs-v2/llms/guide/dana-widget/widget-binding.md).

## API Specification

| Item | Value |
| --- | --- |
| Deeplink Path | `binding` |
| Action | `Open DANA App and show agreement page` |
| URL Schema - Prod | `https://m.dana.id/n/link/binding` |
| URL Schema - Sandbox | `https://m.sandbox.dana.id/n/link/binding` |

## URL Request Parameter

| No | Field | Type | Length | Required | Condition | Remarks |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `partnerId` | String | Variable, 64 max | Mandatory | - | Unique identifier for partner was generated by DANA, or known as clientId |
| 2 | `timestamp` | String | Fixed, 25 max | Mandatory | - | Transaction date time, in format YYYY-MM-DDTHH:mm:ss+07:00. Time must be in GMT+7 (Jakarta time) |
| 3 | `externalId` | String | Variable, 64 max | Mandatory | - | Information of partner identifier, unique per binding request |
| 4 | `channelId` | String | Variable, 64 max | Mandatory | - | Information of channel identifier |
| 5 | `merchantId` | String | Variable, 64 max | Optional | - | Merchant identifier that is unique per each merchant |
| 6 | `subMerchantId` | String | Variable, 32 max | Optional | - | Sub merchant identifier, known as externalDivisionId must be registered in the DANA system before use. To register a new externalDivisionId, use the Create Division API |
| 7 | `seamlessData` | String | Variable, 512 max | Optional | - | Allows merchants to provide user's phone number during binding, eliminating manual entry. See sample below for seamlessData format |
| 8 | `seamlessData.bizScenario` | String | Variable, 64 max | Optional | - | User's bizScenario |
| 9 | `seamlessData.mobileNumber` | String | Variable, 18 max | Optional | - | User's phone number. If this field is filled in, the user must log in with the number that has been included |
| 10 | `seamlessData.verifiedTime` | String | Fixed, 25 max | Optional | - | Value which states that the mobile number that has been included in seamlessData has verified ownership and does not require OTP verification by the provider, in format YYYY-MM-DDTHH:mm:ss+07:00. Time must be in GMT+7 (Jakarta time) |
| 11 | `seamlessData.externalUid` | String | Variable, 32 max | Optional | - | User identifier on partner application |
| 12 | `seamlessData.deviceId` | String | Variable, 32 max | Optional | - | User's device identifier |
| 13 | `seamlessSign` | String | Variable, 512 max | Conditional | Y:= seamlessData is filled | Please refer sample below to know how to include seamlessSign. The steps to generate seamlessSign are: - The partner uses the private key to sign seamlessData, while the provider will use the partner's public key for the verification process - Sign the seamlessData with generated privateKey and algorithm SHA256withRSA - EncodeBase64 the result of seamlessData which already signed by private key (Second Step) - URLEncode the result of base64 encoded string (Third Step) |
| 14 | `scopes` | Array of String | Variable, 256 max | Mandatory | - | The scopes of the authorization, refer to OAuthScopeEnum |
| 15 | `redirectUrl` | String | Variable, 256 max | Mandatory | - | After successful authorization, users will be redirected to this URL |
| 16 | `state` | String | Variable, 32 max | Mandatory | - | Random string for CSRF protection purposes |
| 17 | `lang` | String | Fixed, 2 max | Optional | - | Service language code. ISO 639-1 |
| 18 | `allowRegistration` | String | Variable, 5 max | Optional | - | If value equals `true`, provider may enable registration process during binding. Default `true` |

### URL Request Parameter Enum Details

#### scopes

| No | Name | Type | Remarks |
| --- | --- | --- | --- |
| 1 | `DEFAULT_BASIC_PROFILE` | String | Query user's maksed identifier |
| 2 | `AGREEMENT_PAY` | String | Agreement pay authentication can be shared, complete agreement pay with accessToken |
| 3 | `QUERY_BALANCE` | String | Allow user to see the user's balance by using `Balance Inquiry` API |
| 4 | `CASHIER` | String | Allow user to complete payment in cashier pages |
| 5 | `MINI_DANA` | String | Allows users to access the Mini DANA home page, which displays user name, masked identifier (mobile number), current balance, and options for top-up and transaction viewing, along with various banners. This requires APIs such as Apply OTT, Account Unbinding, and Transaction History |
| 5 | `PUBLIC_ID` | String | Get user's publicUserId in the `Apply Token` API response. The publicUserId is an unique id for one user and one merchant |

### Notes

#### How to include seamlessData

```json
seamlessData = URLEncode({"mobileNumber":"62822999999","bizScenario":"PAYMENT","verifiedTime":"2020-12-23T07:44:11+07:00","externalUid":"7381273821udasudy712368213","deviceId":"637216gygd76712313"})
```

#### How to include seamlessSign

```json
seamlessSign = URLEncode(Base64.encode(sign(seamlessData,privateKey)))
```
