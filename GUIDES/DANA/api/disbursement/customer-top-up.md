# Customer Top Up

```http
POST /rest/v1.0/emoney/topup
```

This API is used for merchant to do top up request to DANA. For the easiest integration, use DANA's Libraries to implement  [Disbursement to Balance](https://dashboard.dana.id/api-docs-v2/llms/guide/disbursement/disbursement-to-balance.md).

## API Specification

| Field | Value |
| --- | --- |
| Expected Timeout | 8 second |
| SNAP Service Code | 38 |
| Accept | application/json |
| Content Type | application/json |

---

### Idempotent Key & Usage Rules

- Idempotent is controlled by Idempotent Key (`partnerReferenceNo`). With two scenarios which are: Idempotent success: Request has been created and the process was successful, will return **2003800**.

- Idempotent failed: Request has been created and the process was failed, will return **5003800**.

1. Response codes with the same request payload indicate the same idempotent processing result.
- Before merchant wants to retry the request with the same partnerReferenceNo, merchant should ensure the consistency of request such as amount or payee user based on access token/customerNumber.

### Retry Mechanism

The following are the details of the retry mechanism in case merchant needs to initiate a retry process:

- Retry is a mandatory process.

- The maximum retry is 5 times.

- Using the following interval time: 5, 10, 20, 40, 60, till merchant's cut off (in seconds).
