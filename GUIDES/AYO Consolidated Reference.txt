# AYO — Sales & Coordination App

## 1. PRODUCT OVERVIEW

AYO is a sales and coordination application for the SellMore POS product.

### 1.1 Roles
| Role  | Description |
|-------|-------------|
| L1    | Field agent. Acquires merchants. Earns commission. |
| L2    | Sales coordinator. Recruits, trains, guides L1. Earns override. |
| Admin | Full control. Users, pricing, payout, reports, configuration. |

### 1.2 Platform
- PWA / mobile web first.
- Responsive for tablet and desktop.
- L1, L2, Admin all access via same PWA with role-based routing.
- SellMore app embeds the AYO SDK for merchant identity, path-lock enforcement, self-renewal, and lifetime activation. Codes and seats reside on the AYO server.

### 1.3 Core Loop
Subscription path:
L1 selects SellMore subscription plan.
AYO creates single-use payment link.
Merchant pays via QRIS or card.
Code generated after payment success (earning PENDING).
L1 sends code to merchant via WhatsApp.
Merchant enters code in SellMore (AYO SDK).
Attribution resolved (earning CONFIRMED).
Payout calculated and paid.
L2 earns override from eligible L1.

Lifetime path:
L1 selects SellMore lifetime plan.
AYO creates deep link carrying L1 attribution.
Buyer taps link -> SellMore app opens.
Path-lock check (must be PROSPECT, before payment).
Buyer pays inside SellMore -> full commission to L1.
Seat pool created (1 seat Single / 2 seats Duo).
Buyer activates or gifts seats.

## 2. PRODUCT PRICING & COMMISSION

Source: L1 Commission Scheme.

| Plan             | Price          | L1 Commission |
|------------------|----------------|---------------|
| Monthly          | 70.000/month   | Y1: 50% · Y2: 40% · Y3: 30% · Y4+: 0% |
| Yearly           | 600.000/year   | Y1: 50% · Y2: 40% · Y3: 30% · Y4+: 0% |
| Lifetime (1 user)| 1.500.000      | One-time 33.33% = 500.000 |
| Lifetime Duo     | 2.000.000      | One-time 35% = 700.000 |

Commission is percentage-based and follows price changes automatically.

### 2.2 Lifetime Products — Unified Seats
- Lifetime products use seats, not codes. No code box.
- Single Lifetime = 1 seat. Lifetime Duo = 2 seats. One unified mechanism.
- Full one-time commission (500.000 / 700.000) recognized at successful payment to the selling L1.
- Each seat activated by a PROSPECT = 1 acquisition. Duo both activated = 2 acquisitions.
- Buyer receives a seat pool. Default suggestion: "Use 1 for yourself." Buyer may assign/gift any seat, including all of them.
- Single Lifetime: seat auto-assigned to buyer at payment (seamless).
- Seat activates via tap-to-activate link + path-lock check (PROSPECT only).
- Seat blocked for a non-prospect -> returns to buyer's pool, re-giftable. No refund.
- Seat link expires in 30 days. Seat value remains; link regenerable.

### 2.3 Renewal Incentive
- One-time 2% of a subscription renewal payment, paid to the L1 who generated the renewal code.
- Applies only to Monthly/Yearly renewals where the redeeming merchant already existed before this payment.
- Never applies to first-time acquisition, Lifetime, or Lifetime Duo.
- Not paid on self-renewal.
- Enters the seller's gross commission (subject to Warm/Cool hold, L2 fee base, Jaminan calculation).

## 4. SELL FLOW

### 4.1 Payment Link (Subscription)
- L1 selects subscription plan.
- AYO creates single-use payment link.
- Link expires after 24 hours.
- No cancel action. Expired/failed links require new link.
- L1 does not enter merchant data.

### 4.2 Payment Link Statuses
SHARED / PAID / FAILED / EXPIRED

### 4.3 Subscription Payment Flow
L1 selects plan. AYO creates link (SHARED).
L1 sends link via WhatsApp. Merchant pays via QRIS/card.
Payment success -> PAID. Code generated (UNUSED). Earning PENDING to seller.
L1 notified. L1 sends code via WhatsApp (code only).
Merchant enters code in SellMore (AYO SDK). SDK reports redemption + identity.
Attribution resolved -> earning CONFIRMED. Code -> USED. Redemption type recorded. Store name updated.

### 4.4 Payment Link Fields
id, l1Id, planId, amount, status, createdAt, expiresAt, paidAt, failedAt, codeIds[]

### 4.5 Lifetime Deep Link
- L1 selects lifetime plan. AYO creates deep link carrying L1 attribution.
- Link sent via WhatsApp as clickable URL.
- Link routes into SellMore app (SDK context). SellMore must be registered as link handler (universal link / app link / shared target).
- Identity + path-lock check happen inside SellMore BEFORE payment.
- Payment happens inside SellMore via AYO SDK.
- Fallback: if SellMore not installed, web page prompts install/open SellMore. Plain web browser payment NOT permitted for lifetime.

### 4.6 Subscription Renewal Flow
L1 creates renewal link (or merchant self-renews).
Merchant pays -> code generated (if via link) -> earning PENDING to seller.
Merchant enters code in SellMore renewal box. SDK reports redemption + identity.
AYO resolves: New merchant -> NEW_SALES to seller + acquisition.
Existing merchant -> RECURRING to owner + 2% RENEWAL_INCENTIVE to seller.
Earning CONFIRMED.

### 4.7 Self-Renewal Flow
Merchant taps self-renew in SellMore -> pays via AYO SDK.
SDK reports (identity known) -> RECURRING to owner CONFIRMED immediately. No 2%.

## 5. CODE LIFECYCLE

### 5.1 Scope
Codes apply to subscription products ONLY. Lifetime uses seat links (no codes).

### 5.2 Code Statuses
UNUSED / USED / EXPIRED

### 5.3 Code Rules
- Code generated only after payment success.
- UNUSED code expires after 7 days.
- USED code remains USED. Subscription status separate.
- Code USED updates store name from SellMore/Applocator.
- Code USED records redemption type: FIRST_ACTIVATION or RENEWAL.

### 5.4 Code Fields
id, code, paymentLinkId, l1Id, planId, status, generatedAt, expiresAt, usedAt,
storeName, originalCodeId, replacementCodeId, redemptionType

### 5.5 Code Reissue
- Only EXPIRED code reissued by Admin. Replacement UNUSED, expires 7 days from reissue.
- No new commission. One active replacement per original. Acquisition counts when replacement USED by new merchant.

## 6. EARNING vs ACQUISITION

| Event                  | Trigger |
|------------------------|---------|
| L1 earning             | Successful payment (PENDING for code-based; CONFIRMED when resolved) |
| Acquisition target     | First-time activation |
| Warm/Cool/Cold count   | First-time activation |
| Jaminan Income target  | First-time activation |
| L1 tenure start        | First successful payment |
| Merchant owner set     | First code USED / first seat activation |

First-time activation = (a) subscription code USED by a NEW merchant, or (b) lifetime seat activated by a PROSPECT. Renewals never count.

### 6.1 Cross-Month Example
Payment 31 Jan; code USED 1 Feb -> earning in January, acquisition in February.

### 6.2 Code Expired Unused
Earning remains (CONFIRMED to seller as NEW_SALES). Acquisition NOT counted.

### 6.3 Pending Attribution
- Code-based earnings PENDING at payment; CONFIRMED at USED (per ownership rules) or EXPIRED (to seller).
- Self-renewal CONFIRMED immediately. Lifetime CONFIRMED at payment.
- Payout includes ONLY CONFIRMED earnings. PENDING shown with "pending" indicator.

## 7. GUARANTEE SCHEME (JAMINAN INCOME)

### 7.1 Rules
First 3 months only. Monthly target 10. Condition >=8 (80%). Top-up to 3.000.000. Below 8 = no top-up. Counting: first-time activations only.

### 7.2 Calculation
If tenureMonth <= 3 AND activatedCustomers >= 8 AND gross < 3.000.000
THEN jaminan = 3.000.000 - gross ELSE 0.

### 7.3 Examples
2.200.000 & 8 -> 800.000 | 2.200.000 & 7 -> 0 | 3.100.000 & 9 -> 0 | 2.900.000 & 10 -> 100.000

### 7.4 Display Rules
Jaminan separate from gross. Included in total income. Excluded from L2 fee base (default).

## 8. WARMTH RULE

### 8.1 Rules (after Month 3, ongoing; counts first-time activations only)
Warm: 5+ -> 100% payout, 0% held.
Cool: <5 -> 80% payout, 20% held.
Cold: <5 for 3 months straight -> 50% payout, 50% held.

### 8.2 Labels: Warm / Cool / Cold

### 8.3 Examples
Warm 2.000.000 -> 2.000.000/0 | Cool -> 1.600.000/400.000 | Cold -> 1.000.000/1.000.000

### 8.4 Months 1-3: Warmth NOT active; Guarantee applies; no held.

## 9. HELD MONEY

### 9.1 Critical Rules
Held NEVER forfeited. Temporarily paused. Hit 5+ new customers in any month -> ALL held released in full.

### 9.2 Release Logic
If currentMonthActivations >= 5 THEN releasedHeld = currentHeldBalance; heldBalance = 0.

### 9.3 Example
Held 400.000; activations 6 -> Warm; released 400.000; held 0.

### 9.4 Accounting Flow
Held = liability "L1 held commission". On release: held liability down, unpaid liability up, paid next payout, no extra L2 fee.

### 9.5 Termination/Suspension
Held remains liability. Admin manual release with reason + audit log.

## 10. L1 TENURE & TARGET

### 10.1 Tenure Start: first successful payment; calendar month counting.

### 10.2 Target Table
M1-3:10 | M4-6:12 | M7-9:15 | M10-11:18 | M12+:20 (admin configurable)

### 10.3 Target Counting: first-time activations only. Payment alone does not count. Renewals do not count.

## 11. L1 PAYOUT

### 11.1 Frequency: Weekly default; per-L1 monthly override; global default configurable.
### 11.2 Weekly: Mon-Sun period; paid next Wednesday.
### 11.3 Monthly: 1st-last; paid 5th next month.
### 11.4 Breakdown: Gross + Jaminan - Held + Released held +/- Adjustment = Payable.
### 11.5 Example: 2.450.000 + 0 - 350.000 + 0 + 0 = 2.100.000.
### 11.6 Statuses: Scheduled / Paid / Failed.
### 11.7 Payout profile must be complete; else prompt.
### 11.8 PENDING earnings excluded from payout until CONFIRMED.

## 12. L1 EARNING DISPLAY

### 12.1 Rules: Earning = gross. Held not deducted. Jaminan separate. Total = gross + Jaminan.
### 12.2 Components: New sales commission; Recurring commission (owner Y); Renewal incentive (2%); Jaminan (separate).
### 12.3 Period Views (for comparison & motivation):
All-time earning (since first payment); YTD (since 1 Jan current year); Last month (previous calendar month). Gross, before held; Jaminan separate.
### 12.4 Earning vs Payout: Earning page gross; Payout page net after held/release.

## 13. L1 PROJECTION

### 13.1 Assumptions: active recurring only; LTV = 3 years; no churn; future new sales NOT included; renewal incentive NOT included.
### 13.2 Rules: horizon = min(remaining 36-month window, plan LTV). Monthly -> monthly payments to window end. Yearly -> yearly renewals to window end. Lifetime -> none. Follows Y1/Y2/Y3/Y4+ by payment date. After window -> 0.

## 14. MERCHANT OWNERSHIP & RENEWAL SCHEME

### 14.1 Ownership
Owner = L1 whose code first activated merchant. Permanent. Never transfers by sale. Admin reassign only as dispute/suspension resolution (reason + audit).

### 14.2 Earning Window & Y-Year
Window = 36 calendar months from merchant's FIRST successful payment.
Y1 (0-12): 50% | Y2 (12-24): 40% | Y3 (24-36): 30% | Y4+ (36+): 0%.
Rate by PAYMENT DATE (not expiry/coverage). Pauses/churn do NOT stop clock.

### 14.3 Renewal Commission Routing
Self-renewal: owner Y, no seller, no acq.
Renewal via owner code: owner Y + owner 2%, no acq.
Renewal via other L1 code: owner Y + seller 2%, no acq, ownership unchanged.
First-time activation: seller full Y1, acq YES.

### 14.4 After 36-Month Window
Self-renewal: owner 0. Code: owner 0, seller 2% only, no acq.

### 14.5 Plan Switch & Churn Return
Plan switch adds period to current expiry; tenure continues; no reset.
Early renewal allowed; commission by payment date.
Churn return: new period from code USED date; owner keeps rights within window.

### 14.6 Owner Suspended/Leaves
Owner-side recurring FROZEN as liability. Admin resolves: reassign ownership OR settle to company (reason + audit).

### 14.7 Worked Example (MA, owner L1-A, first pay 8 Aug 2026)
1: 8 Aug 26 Monthly via L1-A, M1->Y1, 35.000, exp 7 Sep 26.
2: 7 Sep 26 self-renew Yearly, M1->Y1, 300.000, exp 7 Sep 27.
3: 7 Sep 27 Monthly via L1-B, M13->Y2, owner 28.000 + L1-B 1.400, exp 7 Oct 27.
4: Oct 27-Jan 28 churn.
5: 1 Feb 28 Yearly via L1-B, M18->Y2, owner 240.000 + L1-B 12.000, exp 1 Feb 29.
6: 1 Feb 29 self Yearly, M30->Y3, 180.000, exp 1 Feb 30.
7: 1 Feb 30 after window, M42->Y4+, owner 0, seller 2% if code.

## 15. PATH SEPARATION & LIFETIME ACTIVATION

### 15.1 Merchant State Machine
PROSPECT -> Subscribe -> SUBSCRIBED -> (expiry) CHURNED; renew returns to SUBSCRIBED.
PROSPECT -> Buy Lifetime -> LIFETIME (terminal).

| State      | Sees                          | Actions |
|------------|-------------------------------|---------|
| PROSPECT   | Subscribe | Buy Lifetime   | choose one |
| SUBSCRIBED | expiry + renewal box          | renew; no Lifetime |
| CHURNED    | renewal box only              | resubscribe; Lifetime locked |
| LIFETIME   | nothing                       | none |

### 15.2 Activation Methods
Subscription = code box. Lifetime = link-based seat link (no code box).

### 15.3 Triple-Layer Path Lock
L1 Visibility: never show Buy Lifetime to non-prospects.
L2 Link gating: non-prospect opening lifetime link -> "Not available" BEFORE payment.
L3 Activation gating: re-verify PROSPECT at activation.
Design rule: path-lock MUST occur before payment (no-refund constraint).

### 15.4 Direct Purchase (Admin-configurable)
allowDirectLifetimePurchase: false | allowDirectSubscriptionPurchase: false.
When ON with no L1: commission 0 (company retains), no acquisition, no owner.

### 15.5 Ownerless Merchant Rule
Self-activated merchant has no owner and STAYS ownerless permanently. Using L1 code later does NOT establish ownership.
Ownerless uses L1 renewal code: seller 2%; company retains Y%; no acquisition.

### 15.6 Unified Seats Mechanics
1 L1 creates lifetime link -> buyer. 2 Buyer opens -> SellMore identifies -> path-lock. PROSPECT proceeds; else blocked. 3 Buyer pays -> full commission to L1. 4 Seat pool (1/2). 5 Default "use 1 for yourself" (auto-activate) + giftable links. 6 Gift link recipient path-lock: PROSPECT activates (acq); non-prospect blocked -> seat returns to pool.
Seat rules: link expires 30d; value remains; regenerable; buyer may gift both; single auto-assigns; acq on prospect activation; unactivated value = open-ended obligation.
Seat statuses: POOLED / GIFT_LINK_ACTIVE / ACTIVATED.

## 16. L2 COMMISSION

### 16.1 Core Rule: 10% of each eligible L1's total realized income; starts Month 7; window M7-M42.
### 16.2 Decay: M1-6 0% | M7-18 10% | M19-30 6.6% | M31-42 3.3% | M43+ 0%.
### 16.3 Stage Labels: Probation / Active Fee / Decay 1 / Decay 2 / Mature.
### 16.4 L2 Fee Base: L1 gross (new sales + recurring + renewal incentive). Includes held. Excludes Jaminan (default). Optional includeJaminanInL2Base: false.
### 16.5 Examples: M4 0 | M8 400.000 | M20 264.000 | M32 132.000 | M43 0 (on 4.000.000).
### 16.6 Held included in base.
### 16.7 Jaminan excluded by default; if enabled, included.

## 3. GUARANTEE SCHEME (First 3 Months Only)
- Monthly target 10 new customer
- Condition: Achieve ≥80% of monthly target (minimum 8 new customers).
- With 10 visits/day (300 visits/month), 8 customers = just 2.7% conversion.
- Benefit: Company top-up your commission to Rp3.000.000 for that month.
- Note: Below 80% = no top-up for that month.

## 4. WARMTH RULE (After Month 3 — ongoing)

| STATUS  | NEW CUSTOMERS THIS MONTH | PAYOUT | HELD AMOUNT |
|---------|--------------------------|--------|-------------|
| Warm    | 5+                       | 100%   | 0% held |
| Cool    | <5                       | 80%    | 20% held temporarily |
| Cold    | <5 for 3 months straight | 50%    | 50% held temporarily |

## 5. HELD MONEY — CRITICAL RULE
- Held money is NEVER forfeited.
- It is temporarily paused.
- As soon as you hit 5+ new customers in any month, ALL previously held money is released to you in full.

## 3. L2 COMMISSION STRUCTURE
- L2 earns 10% of EACH L1 agent's total realized income (all commissions earned by that L1).
- L2 commission starts from MONTH 7 of each L1 agent's tenure (skipping the first 6 months of probation/ramp).
- L2 decay (applied to the 10% fee) per L1's tenure:

| TENURE (L1 age) | L2 DECAY FACTOR | EFFECTIVE L2 FEE |
|-----------------|-----------------|------------------|
| Month 1–6       | 0%              | 0% (no fee) |
| Month 7–18      | 100%            | 10% of L1 income |
| Month 19–30     | 66%             | 6.6% of L1 income |
| Month 31–42     | 33%             | 3.3% of L1 income |
| Month 43+       | 0%              | 0% (L1 fully matures) |

- Total earning window per L1 for L2 = 36 months (M7 to M42).
